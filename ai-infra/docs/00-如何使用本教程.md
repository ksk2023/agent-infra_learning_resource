# 第 00 章：如何使用本教程

## 本章导学

AI Infra 横跨体系结构、分布式系统、编译、深度学习和平台工程。最危险的学习方式是试图先补齐所有前置知识。本章帮你建立一个够用的起点，并用产出驱动后续学习。

## 学习目标

完成本章后，你应该能够：

1. 判断自己的起点与目标方向。
2. 建立相互隔离、可复现的实验环境。
3. 说出“会跑”“会分析”“会优化”的区别。
4. 创建第一份学习笔记与实验报告。

## 1. 前置知识检查

不要求全部精通，但遇到缺口要回补：

| 领域 | 最低要求 | 自检问题 |
|---|---|---|
| Python | 类、迭代器、装饰器、虚拟环境、测试 | 能否写一个带测试的小包？ |
| Linux | 进程、文件权限、环境变量、管道、SSH | 能否定位一个进程为何退出？ |
| C/C++ 基础 | 指针、内存、编译与链接 | Kernel 方向必须补，其他方向可后补 |
| 深度学习 | 张量、前向/反向、优化器、Transformer | 能否解释训练一步做了什么？ |
| 系统基础 | 延迟/吞吐、缓存、并发、网络 | 能否区分服务慢与服务排队？ |
| 数学 | 线性代数、概率、基本复杂度分析 | 能否做参数量和显存的量级估算？ |

中文入门可使用 [Datawhale Happy-LLM](https://github.com/datawhalechina/happy-llm) 补模型原理，用 [CS 自学指南](https://github.com/PKUFlyingPig/cs-self-learning) 补计算机基础。它们不是本教程的依赖，可按需选读。

## 2. 环境原则

### 2.1 一个项目一个环境

不要全局安装所有训练与推理框架。PyTorch、CUDA、驱动、FlashAttention、vLLM 等存在版本约束，优先参考上游官方安装矩阵。

```bash
# 仅演示通用流程；具体目录名可替换
python -m venv .venv
# Linux/macOS
source .venv/bin/activate
# Windows PowerShell
# .venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
```

建议：

- 用 `requirements.txt`、`pyproject.toml` 或锁文件记录 Python 依赖。
- 用容器封装系统依赖，但不要把镜像当作逃避版本记录的借口。
- 记录 GPU 型号、驱动、CUDA runtime、框架版本和启动参数。
- 将密钥放在环境变量或密钥管理工具中，不写入教程、配置和 Git。

### 2.2 先验证，再训练

最小环境验证应回答：

- Python 是否来自预期环境？
- 加速器是否可见？
- 一个微小张量运算能否在目标设备执行？
- 保存并重新加载一个小文件是否成功？
- 多进程实验能否正常退出？

不要在首次运行时就加载最大模型。先用小模型验证链路，再逐步增加参数量、序列长度和并发。

## 3. 本教程的四种任务

| 标记 | 目的 | 是否需要 GPU |
|---|---|---|
| 概念练习 | 推导、画图、比较方案 | 否 |
| 最低实践 | 运行一个小实验并留下证据 | 通常否 |
| GPU 实践 | 测量真实 kernel、训练或推理 | 是 |
| 源码任务 | 从问题进入真实项目调用链 | 视项目而定 |

每章资源分为：

- **主干**：与本章直接对应，优先学。
- **进阶**：需要更多前置知识或硬件。
- **索引**：找资料用，不要求从头阅读。

## 4. 如何做一次可信实验

一个最小可信实验至少包含：

1. **问题**：例如“增大 batch 是否改善 decode 吞吐？”
2. **假设**：例如“在 compute 未饱和前会改善，但尾延迟可能上升。”
3. **固定条件**：模型、硬件、精度、输入/输出长度、并发、版本。
4. **变量**：一次只改变一个主要变量。
5. **指标**：不仅报均值，也报 P50/P95/P99、吞吐和资源使用。
6. **原始数据**：保留日志或 JSON/CSV，而不只保留截图。
7. **限制**：运行次数、 warmup、异常值、测量误差与未覆盖场景。

推荐流程：

```text
正确性检查 -> warmup -> 正式测量 -> 重复实验 -> 汇总分布 -> 解释瓶颈
```

## 5. 最低实践：建立你的学习基线

创建 `notes/baseline.md`，回答：

- 我的目标岗位或问题是什么？
- 我能使用什么硬件，每周可投入多少小时？
- 我能独立写出训练循环和 attention 吗？
- 我是否做过性能测量，而不只是看运行时间？
- 16 周后我要展示哪一个可复现项目？

再复制 `templates/experiment-report.md`，用本仓库任意 CPU 实验走一遍报告流程。

## 6. 本章自测

1. 为什么把 CUDA、PyTorch、vLLM 的版本写进实验报告？
2. 为什么“服务平均延迟下降”不足以证明用户体验改善？
3. 为什么无 GPU 模拟可以验证调度逻辑，却不能证明真实吞吐？
4. 一个实验改变了精度和 batch，最终加速 20%，能否得出“量化加速 20%”？

<details><summary>参考思路</summary>

1. 性能、API 和可复现性都依赖版本组合。
2. 平均值会隐藏尾延迟、排队和失败请求，需要分布和 SLO。
3. 模拟不包含真实 kernel、显存带宽和通信开销。
4. 不能，两个变量同时变化，无法归因；需要控制变量。
</details>
