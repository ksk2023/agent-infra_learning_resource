# 第 10 章：推理引擎核心——调度、KV 管理与解码

## 本章导学

高性能推理引擎的核心不是单个 attention kernel，而是让请求生命周期、显存和计算调度协同工作。本章从最小模型理解 continuous batching、paging、prefix cache 和 speculative decoding。

## 学习目标

- 解释 static batching 与 continuous batching 的差别。
- 理解 PagedAttention 解决的管理问题及其边界。
- 分析 prefix cache、preemption、取消和公平性。
- 理解 speculative decoding 与 prefill/decode 分离的收益条件。

## 1. 请求生命周期

```text
到达 -> 校验/排队 -> 分配 KV -> prefill
     -> 每轮调度 decode -> 流式输出
     -> 完成/取消/失败 -> 释放或保留可复用缓存
```

引擎要同时维护：

- 请求状态和输出流。
- 可运行、等待、被抢占的序列。
- KV block 的分配、引用与释放。
- token 预算、显存预算和调度公平性。
- 分布式 worker 与采样/通信状态。

## 2. Continuous Batching

Static batching 常将一组请求固定在一起，等整组完成后才进入下一组；不同输出长度会让短请求完成后留下空位。

Continuous batching 以 engine iteration 为调度粒度，可在运行中让新请求进入、完成请求退出，提高设备利用。但它不保证所有指标都改善：

- batch 增大可能提高单步时间。
- prefill 可能干扰 decode 的 ITL。
- 无限接纳新请求会造成排队、显存压力和尾延迟。
- 调度策略需要定义优先级、公平性和 SLO 约束。

## 3. Paged KV Cache

将 KV 按 block/page 管理，类似虚拟内存中的分页思想：

- 逻辑 token 位置通过映射对应物理 block。
- 请求增长时按需分配 block。
- 减少为最大长度预留整段连续空间造成的浪费。
- 便于共享、换出和抢占等机制组合。

Paging 主要解决内存分配与利用问题，不等于 attention 计算自动免费，也不消除所有碎片；block 内未使用空间和元数据仍存在。

## 4. Prefix Caching 与分层 KV

若多个请求拥有兼容且相同的前缀，可复用其 KV，减少重复 prefill。必须考虑：

- 前缀是否逐 token 一致。
- 模型、dtype、RoPE/位置相关信息和并行布局是否兼容。
- 缓存命中、淘汰、容量与多租户隔离。
- 复用 KV 不等于复用最终输出。

当 GPU HBM 不足时，可将 KV 扩展到主机内存或更远存储，但传输与命中成本必须纳入 TTFT 和吞吐评估。

## 5. Speculative Decoding

基本流程：

```text
小 draft 模型/机制提出多个候选
  -> 目标模型并行验证
  -> 按算法接受或修正
  -> 一次目标模型步骤推进多个 token（接受较多时）
```

收益取决于 draft 成本、接受率、目标模型验证成本、batch 和硬件。实现正确时可保持目标分布或目标解码语义，但“近似接受”算法需要单独说明。高接受率不必然端到端更快，仍需测量。

## 6. 分布式推理与 Prefill/Decode 分离

- TP：在设备间切层内计算，通信频繁。
- PP：按层/stage 切分。
- DP：复制模型实例以承接更多请求。
- EP：MoE 专家分布与 AllToAll。
- Prefill/decode 分离：让两类工作负载使用不同资源池和调度策略。

PD 分离能减少相互干扰并独立扩缩容，但需要传输 KV、增加路由和故障路径。短 prompt、低复用或慢网络下不一定划算。

## 7. 最低实践：调度模拟器

```bash
python code/ch10/batching_simulator.py
```

模拟器比较固定批次与逐迭代插入请求的基本逻辑。任务：

1. 修改请求到达时间与剩余 decode 长度。
2. 记录每轮 active request 数、完成时间和空闲槽位。
3. 增加一个长 prefill 请求，讨论对 decode 公平性的影响。
4. 明确模拟不包含真实 kernel、KV 传输与显存，因此只验证调度逻辑。

## 8. GPU 实践：做一次引擎对照

选择 vLLM 或 SGLang，固定模型与 workload：

- 对照开关 prefix caching（接口以当前版本为准）。
- 扫描 batch/并发与最大 token 预算。
- 观察 TTFT、TPOT、吞吐、显存和缓存命中。
- 记录一次“理论收益没有实现”的案例并分析原因。

不建议在首次实验中同时打开 speculative decoding、量化、PD 分离和新 attention backend，否则无法归因。
