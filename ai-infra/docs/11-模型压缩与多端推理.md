# 第 11 章：模型压缩与多端推理

## 本章导学

压缩的目标是让模型在目标设备、质量约束和 workload 下更好运行，而不是单独追求更小文件。本章重点学习量化，同时把剪枝、蒸馏和端侧部署放进同一评估框架。

## 学习目标

- 区分 weight-only、weight-activation 与 KV Cache 量化。
- 理解 scale、zero point、group size、calibration 与累加精度。
- 设计质量、显存、延迟和吞吐的对照实验。
- 比较数据中心 GPU、CPU 和边缘设备的不同约束。

## 1. 量化的系统含义

将高精度数值映射到低精度表示，通常需要：

```text
q = round(x / scale) + zero_point
x_hat = (q - zero_point) × scale
```

具体是对称还是非对称、per-tensor 还是 per-channel/group、静态还是动态 scale，会影响存储、计算和精度。

权重变小只直接说明权重存储下降。端到端加速还需要：

- kernel 能高效读取和解量化/执行低精度数据。
- 权重读取确为瓶颈，或低精度矩阵计算能被硬件利用。
- 转换、scale 计算和反量化开销没有吃掉收益。
- 质量满足任务要求。

## 2. 量化对象要分开

| 对象 | 主要影响 | 风险 |
|---|---|---|
| 权重 | 模型存储、权重带宽、部分计算 | 异常通道、敏感层精度下降 |
| 激活 | 低精度计算与中间存储 | 动态范围、calibration 代表性 |
| KV Cache | 长上下文与并发容量、KV 带宽 | 长上下文质量、累积误差 |
| 梯度/优化器 | 训练显存与通信 | 收敛与稳定性，属于训练专题 |

W8A8、W4A16 等写法通常分别表示权重和激活位宽，但具体 dtype、group 和 kernel 实现仍需查配置，不能只凭缩写推断。

## 3. Post-training 与训练时适配

- **Post-training quantization（PTQ）**：训练后转换，成本较低，可能需要代表性校准数据。
- **Quantization-aware training（QAT）**：训练/微调中考虑量化误差，成本更高，可能改善质量。
- **剪枝/稀疏**：减少或结构化跳过部分权重/计算，但无硬件和 kernel 支持时稀疏不一定加速。
- **蒸馏**：用教师模型指导更小模型，改变的是模型本身，需要重新评估质量与训练成本。

## 4. 一张公平的比较表

| 维度 | 至少记录 |
|---|---|
| 质量 | 任务指标、长上下文、多语言/代码等目标场景 |
| 性能 | TTFT、TPOT、E2E、吞吐、P95/P99 |
| 资源 | 磁盘、加载内存、显存峰值、KV 容量、能耗（若可得） |
| 工程 | 转换时间、kernel 覆盖、模型兼容性、回滚难度 |
| 条件 | 硬件、版本、shape、batch、输入输出长度、并发 |

量化模型在单请求下更快，不代表高并发下仍保持相同优势；可能瓶颈已经从权重带宽转为计算或调度。

## 5. 端侧与数据中心的不同目标

端侧更关注：

- 可用内存和存储。
- CPU/GPU/NPU/DSP 后端覆盖。
- 功耗、发热和持续性能。
- 模型下载、更新与安全。
- 离线能力与隐私。

[ggml-org/llama.cpp](https://github.com/ggml-org/llama.cpp) 适合学习 C/C++ 本地推理和 GGUF 生态；数据中心引擎则更强调高并发调度、KV 管理和多卡扩展。不要用单一 benchmark 排名推导所有场景。

## 6. 最低实践：量化实验设计

不下载模型也可以先完成方案：

1. 选一个小模型与 3 个固定任务集，其中一个必须反映你的真实场景。
2. 保留高精度基线与至少一种量化版本。
3. 固定 decoding 参数和输入，检查质量。
4. 固定输入/输出长度扫描并发，测量性能与显存。
5. 找到一个“文件变小但速度未提升”的解释路径：kernel、瓶颈、转换开销或测量条件。

## 7. GPU/设备实践

- GPU：比较 PyTorch/目标引擎支持的原生与量化路径。
- CPU/本地：使用 llama.cpp 比较两种已支持格式，记录指令集、线程数与内存。
- 移动端/NPU：优先使用对应官方工具链和示例，不把桌面结果直接外推。

任何模型格式转换都要检查模型权重许可证和第三方量化制品的来源。

## 8. 开源资源

- [pytorch/ao](https://github.com/pytorch/ao)：PyTorch 原生模型优化与低精度方向。
- [NVIDIA/TensorRT-LLM](https://github.com/NVIDIA/TensorRT-LLM)：NVIDIA GPU 上的 LLM 推理优化与运行时。
- [ggml-org/llama.cpp](https://github.com/ggml-org/llama.cpp)：本地和端侧 C/C++ 推理。
- [ONNX Runtime 官方文档](https://onnxruntime.ai/)：跨平台模型推理运行时；本次核验时其 GitHub 主仓库无法访问，暂不列为可用源码入口。
- [mlc-ai/mlc-llm](https://github.com/mlc-ai/mlc-llm)：编译与多设备部署路线。
- [InternLM/lmdeploy](https://github.com/InternLM/lmdeploy)：模型压缩、部署和 serving 工具链。

2. 为什么校准集需要代表真实输入分布？
3. 为什么量化 KV Cache 会改变可承载并发？
4. 非结构化稀疏为什么可能没有实测加速？
