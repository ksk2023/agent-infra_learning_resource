# 第 08 章：数据管线、Checkpoint 与容错

## 本章导学

长训练任务的成本不仅是 GPU 计算，还包括数据供给、保存停顿、故障与无效重跑。生产系统必须把“从哪一步、用哪份数据和状态继续”设计成明确能力。

## 学习目标

- 识别数据加载、预处理、分片和主机到设备传输瓶颈。
- 定义可恢复 checkpoint 的完整状态。
- 区分崩溃、挂起、数值异常和静默数据错误。
- 设计可复现、可恢复、可验证的训练任务。

## 1. 数据管线不是训练之外的附属品

```text
对象存储/本地存储
  -> 读取与解压
  -> 解码、清洗、tokenize
  -> shuffle、shard、batch
  -> pinned memory/主机缓冲区（视实现）
  -> H2D 拷贝
  -> GPU 计算
```

如果生产速度低于消费速度，GPU 会等待。优化前分别测量：

- 存储吞吐与元数据访问。
- CPU 利用率与 worker 调度。
- 每步 batch 准备时间。
- H2D 与计算是否重叠。
- 变长样本造成的 padding 和负载不均。

“增加 DataLoader workers”不总是有效，过多 worker 可能造成 CPU、内存和存储竞争。

## 2. 可复现数据需要记录什么

至少记录：

- 数据集版本或不可变快照。
- 清洗/过滤/去重规则与代码版本。
- tokenizer 及其配置。
- shuffle seed、epoch、样本/分片顺序。
- 各 rank 的数据分片策略。
- 动态数据选择与课程学习状态（若有）。

只保存随机种子并不足以复现跨版本、跨并行度的数据顺序。

## 3. 一个可恢复 checkpoint 包含什么

| 状态 | 为什么需要 |
|---|---|
| 模型参数 | 恢复模型本身 |
| 优化器状态 | 延续动量等更新状态 |
| 梯度/分片元数据 | 与并行策略匹配 |
| 学习率 scheduler、step/epoch | 延续训练日程 |
| AMP scaler（若适用） | 保持混合精度状态 |
| RNG 状态 | 尽可能延续随机序列 |
| 数据游标/sampler 状态 | 避免无意重复或跳过数据 |
| 配置、代码与依赖版本 | 知道如何解释和加载 |

只保存模型权重可以用于推理或重新训练，但通常不等于无缝续训。

## 4. 保存过程也要工程设计

推荐风险清单：

- **部分写入**：进程中断留下看似存在的坏 checkpoint。
- **覆盖唯一好副本**：新文件损坏时旧恢复点也丢失。
- **跨 rank 不一致**：部分分片来自不同步次。
- **存储抖动**：保存期间训练停顿或写失败。
- **加载不兼容**：并行度、模型结构或格式改变。

常见模式是写临时位置、校验完整性与元数据、再原子发布/更新指针，并保留多个恢复点。具体原子性依赖存储系统，不能假设所有对象存储语义相同。

异步 checkpoint 可减少停顿，但需处理快照一致性、内存/主机缓冲和“保存尚未完成时再次故障”的窗口。

## 5. 故障分类与检测

| 故障 | 信号 | 处理重点 |
|---|---|---|
| 进程崩溃 | 退出码、日志、事件 | 自动重启与恢复点 |
| 集合通信挂起 | 心跳缺失、超时、栈/trace | 超时、诊断、隔离故障节点 |
| OOM | 分配失败、显存指标 | 调整内存策略，不盲目反复重启 |
| 数值异常 | NaN/Inf、loss 突刺 | 回退到健康状态并定位数据/精度 |
| 数据静默错误 | 分布异常、评测下降 | 数据校验、版本与审计 |

无限自动重试会放大配置错误。应有重试上限、退避、故障分类和人工介入条件。

## 6. 最低实践：写恢复说明书

为一个训练任务写一份 runbook：

1. 如何找到最近一个完整 checkpoint。
2. 如何验证所有分片、step 和配置一致。
3. 如何使用原并行度恢复。
4. 改变并行度时是否需要离线转换。
5. 如何确认数据游标和优化器状态恢复正确。
6. 恢复后前 10 步要检查哪些指标。

## 7. GPU/集群实践：故障演练

使用小模型和短间隔 checkpoint：

- 在非保存阶段主动停止一个 worker，记录恢复时间与损失步数。
- 在保存阶段停止进程，检查系统是否能识别并跳过不完整恢复点。
- 模拟存储不可写，验证任务是否报警而不是悄悄失去恢复能力。
- 恢复后比较连续运行与故障运行的 step、数据位置和指标趋势。

故障演练要限制在自有测试环境，不要在共享生产集群上随意杀进程或制造网络故障。

## 9. 本章自测

1. 为什么只有 model weights 不足以无缝恢复训练？
2. 为什么异步保存仍需要一致性协议？
3. 训练进程不退出是否代表没有故障？
4. 为什么自动重启不能解决所有 OOM？

<details><summary>参考思路</summary>

1. 优化器、scheduler、数据位置、RNG 和分片状态都可能影响续训。
2. 训练仍在更新状态，需要明确快照点，并处理保存期间再次故障。
3. 可能挂起、等待通信、持续异常或无法取得进展。
4. OOM 常由确定性内存需求导致，重复重启只会重复失败。
