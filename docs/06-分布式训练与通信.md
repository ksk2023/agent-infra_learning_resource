# 第 06 章：分布式训练与集合通信

## 本章导学

多卡训练的关键不是“启动多个进程”，而是让计算、通信和状态同步以正确且高效的方式协作。本章从 rank 与 collective 开始，再进入 DDP。

## 学习目标

- 理解 rank、world size、local rank、node 与 process group。
- 区分 Broadcast、Reduce、AllReduce、AllGather、ReduceScatter 和 AllToAll。
- 解释 DDP 的梯度同步、bucket 与计算通信重叠。
- 计算并测量扩展效率，识别通信和同步瓶颈。

## 1. 分布式进程模型

```text
world_size：参与进程总数
rank：全局进程编号
local_rank：进程在单台机器内的局部编号
node：物理或虚拟计算节点
process group：参与某次集合通信的一组进程
```

每个进程通常拥有自己的模型副本、优化器和数据切片。DDP 中需要保证初始参数一致，并对梯度进行等价同步。

## 2. 集合通信是并行策略的字母表

| 操作 | 直觉 | 常见用途 |
|---|---|---|
| Broadcast | 一个 rank 发给全组 | 初始状态/参数分发 |
| Reduce | 全组归约到一个 rank | 汇总 |
| AllReduce | 全组归约，人人有结果 | DDP 梯度同步 |
| AllGather | 收集所有分片，人人有完整结果 | FSDP 汇聚参数 |
| ReduceScatter | 归约后每人保留一片 | 梯度/状态分片 |
| AllToAll | 每个 rank 向每个 rank 发不同数据 | MoE expert 路由等 |

理解“谁输入什么、谁输出什么、数据量如何随 rank 数变化”，比只背名称重要。

## 3. Ring AllReduce 的量级

对总数据量 `S`、进程数 `P`，常见 ring allreduce 由 reduce-scatter 和 allgather 组成。每个 rank 发送的数据量近似：

```text
2 × (P - 1) / P × S
```

常见建模形式：

```text
T ≈ 2(P-1) × latency + 2(P-1)/P × S / effective_bandwidth
```

它解释了为什么大消息更受带宽影响、小消息更受延迟影响。真实实现可能采用 tree、多通道、拓扑感知或不同算法，不能把 ring 公式当成所有环境的精确预测。

## 4. DDP 的关键点

- 各 rank 处理不同数据分片。
- 反向产生梯度后，通过 AllReduce 等机制保持梯度一致。
- gradient bucket 将小张量合并通信，减少大量小操作开销。
- 在条件满足时，后续层反向计算可与已完成 bucket 的通信重叠。
- 未使用参数、静态图、`find_unused_parameters` 等会影响正确性或性能，应按官方语义使用。
- 数据采样需要正确分片与 epoch shuffle，避免重复或漏样本。

## 5. 多卡不必然更快

```text
单步时间 = 计算 + 未重叠通信 + 数据等待 + 同步/其他开销
scaling_efficiency = throughput_N / (N × throughput_1)
```

当模型小、batch 小、互联慢或负载不均时，通信与启动开销可能超过收益。多机还需要考虑 NVLink/PCIe、RDMA、网络拓扑和拥塞。

## 6. 最低实践：Ring AllReduce 模拟器

```bash
python code/ch06/ring_allreduce.py --size-mib 256 --ranks 8 \
  --bandwidth-gbps 50 --latency-us 10
```

任务：

1. 将 ranks 改为 2、4、8、16，观察每 rank 流量和模型时间。
2. 固定消息大小，降低有效带宽，判断属于延迟还是带宽区间。
3. 写出模拟忽略的因素：拓扑、协议开销、计算重叠、拥塞等。
4. 不将模拟时间写成真实 NCCL benchmark 结果。

## 7. GPU/多进程实践

### 路径 A：本机多进程

用 PyTorch `torchrun` 启动一个极小 DDP 任务，验证：

- 每个 rank 的数据不重复。
- 初始参数一致。
- 梯度同步后更新一致。
- 正常结束并销毁 process group。

CPU/Gloo 可用于控制流学习；其性能不能代表 GPU/NCCL。

### 路径 B：多卡通信

使用 [NVIDIA/nccl-tests](https://github.com/NVIDIA/nccl-tests) 测量 AllReduce 等操作的带宽和延迟。保留消息大小、rank 数、拓扑、NCCL 与环境配置。
