# 第 05 章：单机训练显存与性能优化

## 本章导学

OOM 和训练慢都只是症状。你需要先拆分状态、激活和临时开销，再决定使用混合精度、gradient checkpointing、accumulation 还是分片。

## 学习目标

- 建立可解释的训练显存预算。
- 区分降低峰值显存、减少计算和提高设备利用率的手段。
- 用 profile 验证优化，而不是只看“能跑了”。
- 理解吞吐、收敛和单步时间之间的关系。

## 1. 显存由哪些部分组成

```text
总显存 ≈ 参数 + 梯度 + 优化器状态
       + 激活 + 临时 workspace + CUDA/通信 buffer + 碎片
```

训练时不能只看模型权重文件大小。权重文件可能只含一份参数，训练还要保存反向和更新所需状态。

### 一个条件化的 Adam 示例

若某实现使用：

- FP16/BF16 参数：2 字节/参数；
- 同精度梯度：2 字节/参数；
- FP32 master weight：4 字节/参数；
- FP32 Adam 一阶与二阶状态：8 字节/参数；

则静态部分约为 `2+2+4+8=16` 字节/参数。不同框架可能使用 FP32 参数、不同梯度 dtype、状态融合或分片，因此 **16 不是普适常数**。本仓库计算器会显式列出这些假设。

## 2. 激活为何可能占大头

激活与 batch、序列长度、层数、隐藏维度和实现相关。反向传播通常需要保留或重算中间结果。

- 增大 micro-batch 通常增加激活。
- 增长序列还会影响 attention 相关工作区；高效 attention 可改变中间矩阵的显存复杂度。
- gradient checkpointing 通过丢弃部分中间激活、反向时重算来换显存。
- 释放 Python 引用不等于立即改变 caching allocator 的保留显存，诊断时要区分 allocated 与 reserved。

## 3. 常见手段的取舍

| 手段 | 主要收益 | 代价与风险 |
|---|---|---|
| 减小 micro-batch | 降低激活峰值 | 每步并行度下降，kernel 可能低效 |
| Gradient accumulation | 维持目标全局 batch | 更新间隔变长，更多小步开销 |
| 混合精度 | 降低部分存储并加速适配计算 | 溢出、精度、累加器与硬件支持 |
| Gradient checkpointing | 降低激活显存 | 增加重算时间 |
| 更高效 attention | 降低中间状态/访存 | shape、dtype、硬件约束 |
| 参数/梯度/优化器分片 | 降低单卡静态状态 | 引入通信，见第 06–07 章 |

## 4. 吞吐与收敛不能混为一谈

```text
训练吞吐 = tokens / wall_time
扩展效率 = throughput_N / (N × throughput_1)
```

 samples/s 或 tokens/s 提高，不代表达到目标 loss 的总时间一定下降。改变全局 batch、学习率或数据顺序可能改变收敛。实验报告至少同时记录：

- 每步时间与总吞吐。
- 全局 batch 与优化器更新次数。
- train/validation 指标。
- 显存峰值与失败/重试。

## 5. Profiling 要看时间线

建议先回答：

1. GPU 是否等待 CPU 数据预处理？
2. 前向、反向、优化器各占多少时间？
3. 是否有大量小 kernel、同步或 host-device 拷贝？
4. 是否发生重编译、显存分配抖动或碎片化？
5. 吞吐是否随 warmup、步数或序列长度变化？

先改最大的时间项，再复测。`nvidia-smi` 的瞬时利用率无法替代详细 trace。

## 6. 最低实践：显存预算

运行示例：

```bash
python code/ch05/memory_estimator.py \
  --params 7e9 --weight-bytes 2 --gradient-bytes 2 \
  --master-weight-bytes 4 --optimizer-state-bytes 8 \
  --activation-gib 8 --workspace-gib 2
```

任务：

1. 将参数量换成你正在学习的模型。
2. 写出每种状态的字节假设。
3. 估算 1、2、4 卡“纯复制”与“理想分片”的差别，真实通信留到下一章。
4. 与一次小规模实测对照，列出预算漏掉了什么。

## 7. GPU 实践：做单变量优化

固定模型、数据和步数，依次测量：

- 基线。
- 仅修改 micro-batch。
- 仅开启 gradient checkpointing。
- 仅修改混合精度策略。

每组记录峰值显存、tokens/s、loss 曲线和配置。若某组无法运行，也记录失败点，不要只保留成功的最优组。

## 8. 开源资源

- [pytorch/pytorch](https://github.com/pytorch/pytorch)：自动混合精度、checkpoint、profiler 和 FSDP 的官方入口。

3. 为什么 tokens/s 提高不保证更快达到目标效果？
4. `empty_cache` 能否解决真实的峰值显存不足？
