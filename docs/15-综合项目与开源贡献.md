# 第 15 章：综合项目与开源贡献

## 本章导学

学习成果应当能被他人运行、验证和质疑。本章用四个递进项目整合课程，并给出从 issue 到 PR 的开源实践路径。

## 学习目标

- 将概念、实现、测量和分析整合为可复现项目。
- 用对照实验支持性能结论。
- 阅读真实项目的测试和贡献规范。
- 完成一个小而完整的开源贡献闭环。

## 1. 四个递进项目

详细任务见 `projects/README.md`。

| 项目 | 方向 | 核心证据 |
|---|---|---|
| P1 单机性能分析 | GPU/训练/推理通用 | 显存模型 + roofline + profile + 单变量优化 |
| P2 可恢复分布式训练 | 训练 Infra | DDP/FSDP 对照 + 扩展效率 + 故障恢复 |
| P3 Mini 推理与引擎 Benchmark | 推理 Infra | 调度实现 + KV 估算 + 延迟吞吐曲线 |
| P4 可观测 LLM 服务 | 平台/生产 | SLO + 监控 + 灰度回滚 + 故障演练 |

不要求一次性完成全部项目。根据方向选择一项做深，其他项目可作为第二轮扩展。

## 2. 项目必须包含的证据

```text
README：问题、架构、限制、如何运行
配置：依赖锁、硬件/软件版本、模型与数据说明
代码：最小可读实现与自动化测试
实验：原始数据、命令、对照组、失败记录
分析：图表、瓶颈解释、反例和下一轮计划
安全：无密钥、无未经授权数据、许可证清楚
```

不把“脚本在我机器上跑过”作为完成标准。让另一位学习者按 README 在干净环境中复现，才算通过可用性检查。

## 3. 如何写性能结论

不推荐：

> 优化后速度提升 2 倍，证明方案更优。

推荐结构：

> 在指定硬件、模型、版本、输入/输出长度与并发范围内，方案 A 相比基线 B 改变了某项指标；质量约束和资源代价如下。结果只适用于该工作负载，另一负载下出现反例，可能原因及待验证实验如下。

所有相对提升都同时给出基线绝对值、重复次数、分布和原始数据位置。

## 4. 源码阅读的最小闭环

1. **从一个行为开始**：例如“请求取消后 KV 何时释放”。
2. **固定版本**：记录 commit/tag，避免 main 分支变化导致笔记失效。
3. **找入口和测试**：优先读公开 API、配置、测试和最小示例。
4. **画调用链**：标出核心数据结构的生命周期与所有者。
5. **做最小实验**：日志、断点、测试或小 patch 验证理解。
6. **写回笔记**：说明哪些已证实，哪些只是推断。

不要以“读完整个仓库”为目标。真实项目会不断变化，围绕问题建立可复用的阅读方法更重要。

## 5. 开源贡献路线

### 5.1 选择贡献

优先顺序：

- 修正可复现的文档错误或小 bug。
- 补充缺失测试或 benchmark 条件。
- 改进错误信息、示例和可观测性。
- 经讨论后再做性能优化或大型重构。

### 5.2 提交前

- 阅读贡献规范、行为准则、许可证和 CLA/DCO 要求。
- 搜索已有 issue/PR，避免重复。
- 用最小复现说明问题，附环境与版本。
- 将改动控制在单一主题，运行相关测试和格式检查。
- 性能 PR 提供 benchmark 方法、正确性与回归风险。
- 不复制无授权内容，不提交密钥或大体积无关制品。

### 5.3 Review 中

回应可复现问题和技术证据，不围绕 Star、头衔或情绪争论。若上游认为改动不适合，保留你的实验仓库和结论，仍然是一次有效学习产出。

## 6. 最终验收清单

- [ ] 我能用一张图解释系统，而不是只列框架。
- [ ] 我做过至少一个带原始数据的对照实验。
- [ ] 我推导过显存、KV 或通信的量级。
- [ ] 我读过真实项目的一条完整调用链和测试。
- [ ] 我记录过一个失败假设与反例。
- [ ] 我的项目可由他人在干净环境运行。
- [ ] 我没有把模拟结果写成真实 GPU/集群结论。
- [ ] 我检查过代码、模型、数据和文档的许可证。

## 7. 毕业后继续深入

- 训练：Megatron-LM、TorchTitan、DeepSpeed 的并行、通信、checkpoint 与新模型支持。
- 推理：vLLM、SGLang、TensorRT-LLM、Dynamo 的调度、KV、分离式 serving 和多硬件支持。
- Kernel：GPU MODE、Triton、FlashAttention、FlashInfer、CUTLASS。
- 系统研究：从 MLSys、OSDI、SOSP、NSDI、SIGCOMM 等论文回到开源实现，复现核心图而非只读摘要。
- 平台：Kubernetes、KServe、Kubeflow、Ray 的调度、容错、资源治理与多租户。
