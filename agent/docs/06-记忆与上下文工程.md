# 第 06 章：记忆与上下文工程

## 本章导学

“记住所有对话”既不是必要目标，也通常不是好设计。Agent 需要在有限上下文中获得当前决策所需的信息，同时保证来源、时效、权限和遗忘语义。本章把记忆生命周期与上下文组装分开讨论。

## 学习目标

- 区分工作上下文、 episodic、semantic 与 procedural memory。
- 设计记忆的写入、检索、更新、过期和删除。
- 为指令、状态、证据、历史和工具结果分配上下文预算。
- 防止跨用户泄露、记忆污染和压缩丢失约束。

## 1. 四类状态不要混为一谈

| 类型 | 内容 | 典型存储 | 关键问题 |
|---|---|---|---|
| 工作上下文 | 当前输入、计划、最近观察、临时变量 | 当前 run/thread state | 是否服务当前决策、是否超预算 |
| Episodic memory | 某次任务的经历、失败和结果 | 事件/轨迹存储 | 是否保留证据、何时过期 |
| Semantic memory | 用户偏好、已确认事实、领域知识 | 档案/文档/向量或图存储 | 来源、置信度、时效、权限 |
| Procedural memory | 如何完成一类任务的流程、Skill | 版本化文档和代码 | 审核、版本、适用范围、回归测试 |

会话 checkpoint 是恢复执行的状态，不等于长期用户记忆；向量数据库是检索技术，也不等于完整记忆系统。

## 2. 记忆生命周期

```text
候选产生 -> 去重与分类 -> 来源/权限/敏感级检查
  -> 写入（带作用域、时间、版本）
  -> 按当前任务与身份检索
  -> 注入前重排、压缩和冲突检查
  -> 使用后的反馈
  -> 更正、过期、删除与审计
```

不应把模型说“这很重要”作为唯一写入依据。高价值记忆通常包括用户明确偏好、已验证事实和可复用失败经验；一次性验证码、完整隐私对话和未确认推测不应默认长期保存。

## 3. 作用域与来源

每条记忆至少带：

```text
tenant_id / user_id / thread_id
source_type / source_id / observed_at
confidence 或 verification_status
sensitivity / retention_policy
schema_version
```

检索时先按身份和权限过滤，再做相关性排序。先做向量搜索再在生成前“提醒模型不要跨用户”不是可靠隔离。

来源冲突时，不要简单覆盖：保留多个版本、更新时间和验证状态，让确定性规则或用户解决冲突。

## 4. 上下文是一份预算，不是垃圾抽屉

一次模型调用的上下文可分为：

| 区域 | 优先级 | 压缩策略 |
|---|---|---|
| 稳定指令与安全边界 | 高 | 保持短、版本化，不塞入密钥 |
| 当前目标与硬约束 | 高 | 明确保留，不能被历史摘要覆盖 |
| 当前计划/状态 | 高 | 结构化、只保留活动分支 |
| 当前证据与工具结果 | 中高 | 去重、截断、保留来源和定位 |
| 相关长期记忆 | 中 | 权限过滤后按相关性选取 |
| 原始历史与旧观察 | 低 | 摘要、artifact 引用、按需重新读取 |

上下文窗口更大不代表可以省略信息管理。无关信息会稀释关键约束，也增加成本和注入面。

## 5. 压缩必须可验证

摘要前记录必须保留项：用户目标、硬约束、身份作用域、未完成计划、已发生副作用、未解决错误和证据引用。摘要后做自动检查，并保留原始 artifact 的受控链接。

不要只比较摘要前后 token 数；还要在同一任务集上测量成功率、约束遗忘、引用错误和成本。对涉及金额、时间、ID、否定条件的任务做专项回归。

## 6. 最低实践：运行上下文预算与记忆隔离实验

运行：

```bash
python code/ch06/memory_context.py
```

完成：

1. 为不同作用域写入模拟记忆，验证检索不会跨用户。
2. 让旧记忆过期，验证不再被注入。
3. 缩小上下文预算，观察低优先级历史先被移除。
4. 在旧历史中加入与当前目标冲突的指令，说明为什么它不能覆盖高优先级约束。
5. 写一组压缩回归任务，包含数字、否定条件和未完成任务。

### 验收标准

结果能区分“信息仍存在存储中”与“信息被放入本次上下文”；删除与过期都有可测试语义。

## 7. 源码任务

对照一个状态图运行时和一个长期记忆项目，回答：

- thread state 与跨 thread store 如何分离？
- checkpoint 中是否混入大文档或密钥？
- memory 写入是否经过去重、权限和来源记录？
- 摘要由谁生成，如何验证，如何恢复原文？

## 8. 本章自测

1. 为什么长期记忆不应等同于消息历史全量保存？
2. 为什么相关性检索之前必须先做权限过滤？
3. 上下文压缩后 token 减少 80%，能否说明方案更好？
4. 程序性记忆与普通事实记忆的主要差异是什么？

<details><summary>参考思路</summary>

1. 全量历史含噪声、过期和敏感信息，也不利于检索、遗忘和权限控制。
2. 不相关内容若先进入候选，后续仍可能泄露或被错误注入；隔离应在存储/查询边界执行。
3. 不能，还需验证任务质量、约束保留、证据和成本；压缩可能丢失关键信息。
4. 程序性记忆描述可复用流程与能力，需要版本、适用条件和测试；事实记忆描述已确认状态或知识。
</details>
