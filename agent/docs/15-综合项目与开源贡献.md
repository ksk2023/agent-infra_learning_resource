# 第 15 章：综合项目与开源贡献

## 本章导学

学习成果应能被他人运行、验证和质疑。本章用四个递进项目整合课程，并给出从源码阅读到小型开源贡献的路径。项目目标是证据完整，而不是框架和角色数量最多。

## 学习目标

- 将概念、实现、测量、安全和分析整合为可复现项目。
- 用单变量对照和失败案例支持结论。
- 阅读真实项目的测试、状态与权限边界。
- 完成一个小而完整的文档、测试或 bug 贡献闭环。

## 1. 四个递进项目

详细任务见[阶段项目](../projects/README.md)。

| 项目 | 方向 | 核心证据 |
|---|---|---|
| P1 可终止 Mini Agent | 核心机制 | 动作协议 + 工具契约 + 循环/失败测试 |
| P2 证据驱动研究 Agent | RAG/上下文 | 检索基线 + 引用支持 + 不可回答与注入任务 |
| P3 可恢复业务 Agent | Runtime/安全 | checkpoint + 幂等 + 审批 + 故障与安全演练 |
| P4 可评测协作 Agent | 多 Agent/生产 | 单 Agent 基线 + 重复评测 + trace + SLO/成本 |

根据方向选择一项做深。P4 不要求必须使用多 Agent；若单 Agent 更优，清楚证明并选择简单方案也是高质量结果。

## 2. 项目必须包含的证据

```text
README：用户问题、架构、限制、如何运行
配置：依赖锁、模型/提供方、提示词、工具和环境版本
代码：最小可读实现、自动化测试和明确模块边界
任务：任务来源、成功判据、禁止副作用、保留集
实验：命令、原始轨迹、对照组、重复运行和失败记录
分析：指标、失败分类、反例、成本和下一轮计划
安全：威胁模型、权限、审批、脱敏、沙箱和许可证
```

“我机器上跑通一次”不是完成标准。让另一位学习者按 README 在干净环境复现，并检查其是否获得相同结论与限制。

## 3. 如何写 Agent 结论

不推荐：

> 加入多 Agent 和反思后，系统更智能，成功率大幅提高。

推荐结构：

> 在指定模型、工具、任务集、环境快照和总预算下，方案 A 相比单 Agent 基线 B 改变了最终状态成功率、引用支持率和单位成功成本；重复次数、原始轨迹和失败分布如下。该结果只适用于当前任务，简单任务上出现成本反例，下一轮将验证某项假设。

所有相对提升同时给出基线绝对值、分子/分母、重复次数、无效样本处理和原始数据位置。安全违规不能被平均成功率掩盖。

## 4. 源码阅读的最小闭环

1. **从一个行为开始**：例如“工具超时后，SDK 如何避免无界重试”。
2. **固定版本**：记录 commit/tag，避免 main 分支变化导致笔记失效。
3. **找入口和测试**：优先读公开 API、schema、测试和最小示例。
4. **画调用链**：标出消息、状态、工具调用、checkpoint 和 artifact 的生命周期与所有者。
5. **做最小实验**：用日志、断点、测试或小 patch 验证理解。
6. **写回笔记**：区分已证实事实、源码推断和仍待验证问题。

不要以“读完整个仓库”为目标。围绕一个问题建立可复用的阅读方法更重要。

## 5. 开源贡献路线

### 5.1 选择贡献

优先顺序：

- 修正可复现的文档错误、失效链接或版本说明。
- 补充解析、工具错误、权限或恢复行为的缺失测试。
- 改进结构化错误、trace、示例和安全提示。
- 经讨论后再做新协议、性能优化或大型重构。

### 5.2 提交前

- 阅读贡献规范、行为准则、许可证和 CLA/DCO 要求。
- 搜索已有 issue/PR，避免重复。
- 用最小复现说明问题，附模型、框架、依赖和环境版本。
- 将改动控制在单一主题，运行相关测试和格式检查。
- Agent 行为改动提供固定任务集、轨迹、成本和安全回归。
- 不提交密钥、真实用户数据、大体积无关制品或无授权内容。

### 5.3 Review 中

回应可复现问题和技术证据，不围绕 Star、头衔或情绪争论。若上游认为改动不适合，保留你的实验仓库和结论，仍然是有效学习产出。

## 6. 最终验收清单

- [ ] 我能用一张图解释系统，而不是只列框架。
- [ ] 我实现过一个可终止、可处理错误的最小 Agent Loop。
- [ ] 我有至少 20 条带成功判据和对抗场景的任务。
- [ ] 我做过重复运行，并区分 pass@k 与 pass^k。
- [ ] 我读过真实项目的一条工具或恢复调用链和测试。
- [ ] 我记录过一个失败假设、一个反例和一个安全边界。
- [ ] 我的项目可由他人在干净环境运行。
- [ ] 我没有把模拟模型结果写成真实能力，也没有复制不同版本榜单数字。
- [ ] 我检查过代码、模型、数据和文档的许可证。

## 7. 毕业后继续深入

- **核心运行时**：状态图、durable execution、事件溯源、沙箱和队列。
- **工具与协议**：MCP/A2A 当前规范、SDK 兼容性、能力发现和安全。
- **研究与 RAG**：检索质量、证据压缩、引用验证和深研任务评测。
- **Coding/Computer-use**：真实环境、agent-computer interface、可执行验证与隔离。
- **Agentic RL**：可验证环境、轨迹数据、rollout 系统、奖励与泛化。
- **可信生产系统**：私有评测、SLO、灰度回滚、威胁建模和事故复盘。
