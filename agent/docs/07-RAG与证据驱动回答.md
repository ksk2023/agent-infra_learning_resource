# 第 07 章：RAG 与证据驱动回答

## 本章导学

RAG 不是“把文档转向量数据库，再让模型自由发挥”。对 Agent 而言，检索是获取可核验观察的一种工具；回答质量取决于数据、切分、检索、权限、证据使用和引用检查的整条链路。

## 学习目标

- 解释 ingestion、chunk、index、retrieve、rerank、generate 和 citation 的关系。
- 区分检索相关性、答案正确性与引用支持性。
- 实现一个无外部依赖的词项检索基线。
- 处理空结果、冲突证据、权限与间接提示注入。

## 1. RAG 生命周期

```text
文档与权限
  -> 解析、清洗、去重、保留结构
  -> 切分并记录文档/页/段等定位信息
  -> 建立词项或向量索引
  -> 按身份过滤并检索候选
  -> 可选重排、去重和上下文压缩
  -> 模型基于证据回答或明确信息不足
  -> 校验引用存在、可访问且支持对应结论
```

原始文档、索引快照、embedding/retriever 版本和查询都应能关联。只保存最终回答，无法判断错误来自检索还是生成。

## 2. 检索不是越复杂越好

| 方法 | 优势 | 局限/适用 |
|---|---|---|
| 关键词/BM25 类 | 精确术语、ID、可解释、基线简单 | 同义表达和语义匹配有限 |
| 向量检索 | 语义相似、跨表述 | 精确数字/稀有词可能不稳定，依赖模型与索引 |
| 混合检索 | 兼顾词项与语义 | 融合策略、延迟和调参更复杂 |
| 重排 | 提高顶部候选相关性 | 额外模型成本，可能放大偏差 |

先建立简单基线并构造查询集。若关键词基线已满足业务，不必为了技术名词引入向量基础设施。

## 3. 三层评测

| 层 | 示例指标 | 问题 |
|---|---|---|
| 检索 | Recall@k、MRR、无结果率 | 正确证据是否进入候选、排名是否靠前？ |
| 回答 | 任务正确率、完整性、拒答准确性 | 最终结论是否正确，是否知道信息不足？ |
| 引用 | 引用有效率、引用支持率、定位准确性 | 引用是否存在、可访问并支持该句？ |

高 Recall@k 不保证模型会使用证据；语言 judge 给高分也不保证引用真实。能确定性检查的字段先用代码检查，再对语义支持做人工或经校准的模型评审。

## 4. 证据冲突与信息不足

Agent 应能执行：

- 同一问题检索多份候选，保留来源和时间，不急着合并。
- 冲突时说明范围与差异，必要时查询更权威或更新来源。
- 证据不足时返回缺口和下一步，而非用参数知识补齐后假装有引用。
- 对当前状态问题使用实时工具，而不是依赖旧索引。

“不知道”可以是合格结果；评测集需要包含不可回答和权限不足任务。

## 5. 不可信文档与提示注入

网页、PDF、邮件和检索片段可能包含“忽略规则”“发送数据”等指令。这些文字是证据内容，不是系统控制命令。

防护措施包括：

- 在数据结构中显式标记来源和信任级别。
- 将内容处理与动作授权分离，文档不能授予新工具权限。
- 对检索入库做来源审查、完整性和恶意内容测试。
- 让引用指向具体位置，便于用户核验。
- 对敏感语料执行租户隔离和访问控制，避免跨域检索。

## 6. 最低实践：建立检索与引用基线

运行：

```bash
python code/ch07/rag_lab.py
```

完成：

1. 用示例文档查询关键词，检查排名和对应文档 ID。
2. 添加一个同义表达查询，记录词项基线失败。
3. 提交不存在的引用 ID，验证引用校验拒绝。
4. 添加一个包含恶意指令的文档，验证它只被当作正文，不改变允许动作。
5. 写 10 个查询及相关文档标注，计算 Recall@k。

### 验收标准

能分别指出检索失败、生成失败和引用失败；不要把词项相似度分数解释为事实置信度。

## 7. 真实模型实践

固定文档快照与 30 条问题，对比无检索、关键词检索和一种混合/向量方案。报告检索 Recall@k、回答正确率、引用支持率、P95 延迟与每题 token/工具成本，并加入无答案和恶意文档任务。

## 8. 本章自测

1. 文档被检索到第一名，是否证明最终答案正确？
2. 引用链接真实存在，是否证明它支持附近结论？
3. 为什么 RAG 评测集要包含不可回答问题？
4. 为什么检索结果中的指令不能修改 Agent 权限？

<details><summary>参考思路</summary>

1. 不能，模型可能忽略、误读或过度推断证据。
2. 不能，还需语义支持检查；存在性只是最低门槛。
3. 用于测试系统是否会诚实表达信息缺口，避免强行编造。
4. 检索内容是不可信数据，权限必须由可信身份和策略系统独立决定。
</details>
