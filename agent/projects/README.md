# 阶段项目

四个项目由浅入深。选择一个与目标匹配的项目做深，比同时堆叠多个框架更有价值。每个项目都应提供可运行代码、任务集、原始结果、失败分析和限制。

通用要求：

- 从离线假模型/假工具开始，再按需替换真实能力。
- 不把密钥、个人信息、真实生产数据或任意可执行恶意内容放入仓库。
- 记录代码、数据、模型、文档和依赖的许可证；它们不是同一类授权。
- 结论必须带任务范围、配置、样本量、重复次数和原始证据。

## P1：可终止 Mini Agent

**对应章节**：02–05。

**问题**：实现一个不依赖框架的 Agent Loop，能把模型动作、工具观察、状态和停止条件说清楚。

**建议范围**：2–3 个只读工具，例如白名单计算器、假数据查询和本地文档搜索。不要从无限制 shell 开始。

**必做交付**：

1. 严格的动作 schema 与解析器，区分 `tool_call` 和 `final`。
2. 工具注册表、参数校验、稳定错误结构、超时与调用关联 ID。
3. 最大模型调用数、最大工具数、deadline 和重复动作检测。
4. 至少 20 条任务：正常、空结果、非法动作、未知工具、工具异常、不可完成与需要澄清。
5. 单步轨迹、完整 JSON 结果和单元测试。

**验收标准**：

- 所有路径都会终止；未知工具不会被执行，工具失败会作为观察返回。
- 能用一条轨迹解释观察如何影响下一动作，而不是只展示最终回答。
- 模拟模型结果标为“控制逻辑验证”；若有真实模型，单独报告其成功率。

## P2：证据驱动研究 Agent

**对应章节**：06–07、12、14。

**问题**：对一个明确许可的本地文档集进行检索、证据组织、回答和引用验证，并知道何时应拒答。

**建议范围**：公开文档的自存副本或自行编写的小语料；记录来源、快照日期和许可证。先做单 Agent，不自动赋予联网写操作。

**必做交付**：

1. 文档清单、分块策略、检索基线和查询任务集。
2. Recall@k 等检索指标，以及最终答案的引用存在性和人工支持性抽查。
3. 无答案、冲突证据、过期信息、伪造引用和间接提示注入任务。
4. 上下文预算、记忆作用域与删除策略。
5. 有检索/无检索或两种分块策略的单变量对照。

**验收标准**：

- 每个事实性关键结论能定位到证据；引用不存在时评分器会失败。
- 把“检索到相关内容”和“证据支持答案”分别评价。
- 外部文档中的指令只作为数据处理，不改变工具权限。
- 报告检索失败、生成失败、评分器失败与安全失败的分类。

## P3：可恢复业务 Agent

**对应章节**：08–09、13–14。

**问题**：用完全模拟的业务工具完成一个多步骤流程，在进程故障、重复请求和人工等待后恢复，且不重复副作用。

**建议范围**：假工单或假订单系统；不得连接真实支付、生产数据库或真实邮件。

**必做交付**：

1. 显式 run 状态机、事件日志、artifact 清单与 checkpoint schema。
2. 每个写工具的 `operation_id`、服务端幂等约束和提交状态查询。
3. 在工具调用前、提交后响应丢失、checkpoint 前后分别注入故障。
4. 高风险动作的审批预览；审批绑定身份、工具、规范化参数哈希和有效期。
5. 取消、拒绝、修改、超时、撤销和恢复测试，以及审计 trace。

**验收标准**：

- resume 不重复已确认步骤；丢失响应时先对账，不盲目重放。
- 同一幂等键不生成第二条业务副作用，不同参数复用该键会被拒绝。
- 审批后改变金额、资源或数据去向必须重新审批。
- 能区分进程状态、模型上下文和外部业务状态，不用最终文本代替状态检查。

## P4：可评测协作 Agent

**对应章节**：10、12–15。

**问题**：验证一种协作或编排方案是否在固定任务和预算下优于单 Agent 基线。结论可以是“不值得使用多 Agent”。

**建议范围**：研究、代码审查或故障分诊中的一个窄任务。优先比较单 Agent、确定性 workflow 和一种协作模式。

**必做交付**：

1. 单 Agent 与确定性 workflow 基线，以及一种 handoff、orchestrator-workers 或 agents-as-tools 方案。
2. 至少 30 条私有任务和独立保留集，含困难、对抗、不可完成与工具故障任务。
3. 相同模型、工具和总预算下的重复运行；保存逐次结果、轨迹和环境验证。
4. 最终状态成功率、过程指标、安全违规、P50/P95/P99、总成本和单位成功成本。
5. 失败分类、至少一个反例、SLO 草案和回滚/降级方案。

**验收标准**：

- 不只报告最佳运行；给出原始成功序列、分子/分母、重复次数和无效样本处理。
- 选择器、评审 Agent 和重试的成本也计入总成本。
- 简单任务若出现协作成本反例，应保留并解释，而非删除。
- 若安全违规增加，不能用平均成功率或任务质量掩盖。

## 项目完成后的展示顺序

```text
用户问题与边界 -> 最小架构 -> 可复现命令 -> 基线与对照
-> 原始指标 -> 失败/安全案例 -> 成本 -> 限制与下一步
```

可用 `templates/experiment-report.md` 和 `templates/eval-task.md` 组织证据，用 `templates/source-reading.md` 记录对真实框架的源码核查。
