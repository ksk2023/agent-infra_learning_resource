## 二、16 周标准路线

建议每周 8–12 小时。时间用于阅读、实现、评测和复盘，不包括等待 API 或环境下载。

| 周 | 内容 | 必做实践 | 周产出 |
|---|---|---|---|
| 1 | 00、01 | 判断三个场景该用脚本、workflow 还是 Agent | 全栈图 + 学习计划 |
| 2 | 02 | 解析合法/非法动作并写测试 | 结构化输出边界 |
| 3 | 03 | 跑通模拟模型驱动的工具循环 | 迷你 Agent + 轨迹 |
| 4 | 04 | 新增一个带 schema、超时和错误结构的工具 | 工具契约与测试 |
| 5 | 05 | 构造 DAG，加入失败节点与停止条件 | 任务控制图 |
| 6 | 06 | 对长历史做分层、压缩和权限隔离 | 上下文预算报告 |
| 7 | 07 | 跑检索实验，检查引用是否存在且支持结论 | RAG 对照报告 |
| 8 | 08 | 在副作用前注入故障并恢复 | checkpoint 演练 |
| 9 | 09 | 画 MCP/A2A/Skill 边界并审查工具描述 | 协议与信任边界图 |

## 三、8 周冲刺路线

适合已经会调用 LLM API、做过 Python 项目的人：

1. 第 1 周：01–03，独立写出可终止的最小 Agent Loop。
2. 第 2 周：04–05，补齐工具契约、任务状态和预算。
3. 第 3 周：06–07，完成记忆/上下文与 RAG 引用实验。
4. 第 4 周：08–09，完成 checkpoint、人工中断和协议映射。
5. 第 5 周：10、12，先建单 Agent 基线，再比较多 Agent。
6. 第 6 周：13，补齐 trace、SLO、重试和单位成功成本。
7. 第 7 周：14，完成威胁模型和安全回归。
8. 第 8 周：15，整理项目证据，不追求堆叠框架和角色。

## 四、无 API、有 API 与训练路线

### 无模型 API

可以完成全部概念、任务设计和离线代码实验。模拟模型只能证明 harness 的控制行为，例如“工具结果会回到循环”“达到步数会停止”，不能证明真实 Agent 能完成某类任务。报告中应把这类结论标为“控制逻辑已验证，模型能力待实测”。

### 有模型 API

优先建立小型固定任务集，再替换模型或提示词。保存模型标识、提供方、参数、工具 schema、轨迹和原始结果。不要一开始接浏览器、支付、生产数据库或无限制 shell。

### 有 GPU/训练条件

第 11 章再进入轨迹 SFT、可验证奖励和在线 RL。先确认纯提示、工具与上下文改造已经达到瓶颈，否则训练只会把系统问题隐藏到更昂贵的管线里。

## 五、每周打卡模板

复制 `templates/weekly-checkin.md`，至少记录：

- 本周能独立解释的三个机制。
- 一个最小实现或源码阅读笔记。
- 一组包含任务、配置、原始轨迹和失败分类的实验。
- 一个失败假设及其原因。
- 下周唯一最重要的任务。

## 六、避免四条低效路线

1. **只收集框架**：装十个框架不等于理解一次工具调用的生命周期。
2. **只看成功 Demo**：失败任务、重复运行和越权测试才揭示系统边界。
3. **先上多 Agent**：没有单 Agent 基线，就无法证明协作带来的收益大于成本。
4. **把提示词当安全边界**：授权、隔离、审批和审计必须由模型之外的确定性系统执行。
